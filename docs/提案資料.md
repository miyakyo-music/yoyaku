## 2. 現状: 「りざぶ郎」で予約している

## 4. 新しい予約システムの概要

- 音楽棟の練習室のために作った、予約専用のホームページ
- 予約表の URL: https://miyakyo-music.github.io/yoyaku/
- スマートフォン・パソコンのどちらでも使える
- 利用者は登録不要。今と同じく、名前を書いて予約するだけ
- 予約のデータは、大学の Google アカウントのスプレッドシート（表計算のファイル）に保存される（要確認：保存先が大学の Google Workspace の共有ドライブであること）
- 現在の版: v0.4.0-beta（試験運用中の版）

> 話す内容: 新しいシステムは、ホームページの形の予約表です。アプリを入れる必要はありません。予約の記録は、Google のスプレッドシート、つまり Excel のような表のファイルに残ります。

## 5. 画面の流れ（予約する）

1. 予約表の URL を開く（ブックマークや掲示の QR コードから）
2. 「一覧」で、その日の全部屋の予約状況を見る
3. 空いている所を押す（スマホは1回押すと「＋予約」が出て、もう一度押すと予約画面）
4. 氏名／団体名、学籍番号／所属（任意）、備考（任意）、編集用パスワード（任意・4桁の数字）を入れて「予約確定」
5. 予約表にすぐ反映される

- 2回目からは、名前などが自動で入る（その端末に記憶）

> 話す内容: 予約の手順は今とほぼ同じです。スマホでは、スクロールしようとして指が触れただけで予約画面が開いてしまわないよう、1回目は「＋予約」の印を出すだけにしています。

---

## 6. 画面の流れ（見る・変える・取り消す）

- 表示は3種類
  - 「一覧」: 1日分の全部屋
  - 「部屋別」: 1つの部屋の予約を、選んだ日から1か月分、日ごとに並べて表示
  - 「カレンダー」: 月ごとの表示（部屋を選ぶとその部屋の予約、すべての部屋なら件数）
- 予約を押すと詳細が出て、「変更」「取消」ができる
  - 編集用パスワードを付けた予約は、その4桁を知っている人だけが変更・取消できる
- 「自分の予約」で、その端末で作った予約の一覧を見られる
- 予約表は1分ごとに自動で最新の状態になる

> 話す内容: 予約を押すと詳しい内容が見られ、そこから変更や取消ができます。いたずらで消されないよう、予約のときに4桁の編集用パスワードを付けておけます。

## 7. スマートフォンで使いやすく

- 画面の幅に合わせて、スマホ用の配置に自動で切り替わる
- 指2本で広げる・縮める（ピンチ）と、時間の目盛りの幅を変えられる
- 長押ししてから指でなぞると、予約する時間を指定できる
- iPhone・Android・パソコンの主なブラウザで動作を確認する方針（iOS 15.4 以降で完全に対応）
- 「空室」ボタン: 今から30分以上空いている部屋だけを、「○時まで空き」と添えて表示

> 話す内容: 学生はほとんどスマホで予約するので、スマホでの使いやすさを特に大切にしました。「空室」ボタンを押すと、今すぐ使える部屋だけが出てきます。練習室の前で空き部屋を探すときに便利です。

## 8. 限定公開の部屋（演習室など）

- 先生方や特定の学生だけが使う部屋（演習室など）を「限定公開」にできる
- 一般の学生の予約表には、その部屋があること自体が表示されない
- 使う人だけに、専用の入口の URL とパスワードを伝える
  - 入口: https://miyakyo-music.github.io/yoyaku/?limited
  - パスワードを一度入れた端末では、次からは入力不要
- パスワードが広まったときは、管理画面で変えれば、それまでの端末でも見えなくなる
- このほか「管理者のみ」予約できる部屋、「使用停止」（故障・改修中）の部屋も設定できる

> 話す内容: 演習室のように、限られた人だけが使う部屋を同じ予約表で扱えます。一般の学生にはその部屋が見えないので、混乱が起きません。どの部屋を限定公開にするかは、先生方に決めていただきたい点の一つです。

## 9. 管理画面でできること

管理画面（予約表の右上の歯車「管理」から。管理用パスワードで入る）

- 「練習室」: 部屋の追加・削除・名前の変更・並べ替え、ピアノの種類などの表示（例: 大・GP）、予約制限
- 「利用時間・制限」: 予約表のタイトル、お知らせ、利用できる時間（初期値 7:00〜22:00）、予約の単位（初期値 5分）、1回の最大予約時間、何日先まで予約できるか、定休日
- 「休館・利用停止」: 入試・調律・清掃などで使えない日・部屋・時間帯を登録
- 「パスワード」: 限定公開の部屋のパスワード、管理用パスワードの変更
- 「不具合報告」: 利用者から届いた報告の確認
- 「データベース」: 予約の記録が入ったスプレッドシートを開く

> 話す内容: 事務的な設定は、すべて管理画面からできます。たとえば入試の日を休館にすると、予約表に灰色で理由が表示され、その日は予約できなくなります。お知らせは通常の青い帯と、重要な赤い帯を選べます。

---

## 10. 不具合報告の仕組み

- 予約表の下や上部の帯にある「不具合を報告」から、利用者が直接送れる
- 内容と、任意の連絡先、使っている端末の種類・画面の大きさなどが一緒に届く
- 管理画面で「未対応」「対応中」「対応済み」「対応しない」の状態を付けて管理
- 未対応・対応中の件数が、管理画面の入口に数字で表示される

> 話す内容: 試験運用の間は特に、使いにくい点を早く見つけて直すことが大切です。学生が気づいたことをその場で送れるようにしています。

## 15. 安全のための仕組み

- 管理用パスワード（6文字以上）: 管理画面に入るためのもの。プログラムの中ではなく Google 側に保管しており、公開されているプログラムからは見えない
- 編集用パスワード（4桁の数字・任意）: 予約ごとに付けられる。画面には表示されず、利用者の画面にも送られない
- パスワードを何度も試す攻撃への対策
  - 編集用パスワードを同じ予約で5回続けて間違えると、その予約は10分間操作できない
  - 管理用パスワードを10回間違えると、10分間受け付けない
  - 限定公開のパスワードを全体で30回間違えると、10分間受け付けない
- 同じ時間に2人が同時に予約しても、二重予約にならない（後の人には「重複しています」と表示）
- 予約の入力欄に、表計算の数式として悪用される文字（先頭の = + - @）は入れられない
- 予約者の名前は自己申告。なりすましを完全に防ぐ仕組みではない

> 話す内容: 大切な情報は、公開されているプログラムには含まれていません。パスワードを総当たりで試されても、一定回数で止まるようにしています。ただし、名前は自己申告ですので、なりすましを完全に防ぐものではない点はご了承ください。必要になれば、大学の Google アカウントでのログインを必須にする方法も検討できます。

## 17. 起こりうる問題と対策

| 起こりうること | 対策 |
| :--- | :--- |
| 担当の学生が卒業して、誰も直せなくなる | 先生を含む2人以上を管理者にする。引き継ぎの手順書を用意済み。現在 GitHub の団体の管理者は1人だけなので、早めに追加したい |
| 担当者の Google アカウントが卒業で消え、システムが止まる | 予約の記録は共有ドライブに置く。卒業前に後任者のアカウントで設定し直す（手順書あり） |
| Google や GitHub のサービスが止まる | 予約表が一時的に使えなくなる。復旧を待つ。長引く場合は掲示や紙で受け付ける（要確認：その場合の代わりの方法） |

| 予約の記録を誤って消してしまう | スプレッドシートの「版の履歴」から戻せる。定期的にコピーを取る |
| 不具合で予約できなくなる | 直前の版に戻す手順を用意している |

> 話す内容: いちばん心配なのは、担当の学生が卒業したあとのことだと思います。そのために、先生にも管理者に加わっていただき、手順書をそろえました。
