# 06 トラブルシューティング

対象: 管理者・システム担当者。画面に出る文言は、`web/api.js`・`web/index.html`・`web/admin.html`・`gas/Code.gs` に書かれているものと同じです。

## まず確かめること

1. GAS の URL（`web/config.js` の `GAS_API_URL`）をブラウザで直接開く。
   - `{"ok":true,"service":"練習室予約API","apiVersion":1,"serverNow":"..."}` と出れば、サーバーは動いています。
   - Google のログイン画面やエラーのページが出る場合は、GAS のデプロイに問題があります（「3. GAS の権限・デプロイのエラー」）。
2. GitHub の「Actions」タブで、最後の「GitHub Pages に公開」が成功しているか見る。
3. 利用者から不具合報告が届いていれば、管理画面の「不具合報告」→「端末・環境の詳細」で、版（`appVersion`）・端末・直近のエラー（`lastError`）を見る。
4. Apps Script エディタの左の「実行数」で、エラーになった実行がないか見る。サーバーの中のエラーの詳しい内容は、利用者の画面には出ず、ここに記録されます（`doPost` が `console.error` で記録している）。

## 1. 予約表が表示されない・通信のエラー

| 画面の文言 | 原因 | 対処 |
| :--- | :--- | :--- |
| 「接続先が設定されていません（web/config.js の GAS_API_URL）。」 | `web/config.js` の `GAS_API_URL` が空 | GAS のウェブアプリの URL を書いて `main` に push する |
| 「通信に失敗しました。インターネット接続を確認してください。」 | 端末がネットにつながっていない。または GAS に届かない（URL の誤り、「アクセスできるユーザー」が「全員」でない、デプロイした人のアカウントが使えなくなった など） | 端末の接続を確かめる。つながっているなら「まず確かめること」の1。デプロイした人のアカウントが失効していれば [05_引き継ぎ手順.md](05_引き継ぎ手順.md) の C を行う |
| 「サーバーの応答がありません。時間をおいて再度お試しください。」 | 60秒たっても応答がない（GAS が混んでいる・Google の障害） | 時間をおいて再度試す。続く場合は Google のサービスの状況を確かめる |
| 「サーバーに接続できませんでした（（番号））。時間をおいて再度お試しください。」 | GAS が正常でない応答を返した | 番号を控えて時間をおいて再度試す。続くなら GAS の URL を直接開いて確かめる |
| 「サーバーの応答を読み取れませんでした。時間をおいて再度お試しください。」 | JSON 以外（Google のログイン画面やエラーのページなど）が返った | 「アクセスできるユーザー」が「全員」か確かめる。URL が末尾 `/exec` か確かめる（`/dev` は使えない） |
| 「サーバーでエラーが発生しました。時間をおいて再度お試しください。」 | GAS の中でエラーが起きた。よくあるのは、シート名が変わった・シートが消えた（記録には「シート『予約台帳』が見つかりません。…」と残る） | Apps Script の「実行数」で内容を見る。シートの問題ならシート名を戻すか、メニュー「予約システム > 初期セットアップ」を実行する |
| 「不明な操作です。」 | 画面が呼んだ処理が GAS にない（画面だけ新しく、GAS が古い） | GAS を最新の `gas/Code.gs` で再デプロイする（[03](03_保守・更新手順.md)） |
| 「部屋が登録されていません（部屋マスタを確認してください）。」 | 部屋マスタに部屋がない | 管理画面の「練習室」で部屋を追加する |
| 「アクセスが集中しています。少し待ってから再度お試しください。」 | 同時に多くの操作があり、10秒待っても順番が回ってこなかった | 少し待って再度試す |

## 2. 版の不一致の警告

画面の下に「システムが更新されました。ページを再読み込みしてください。」と出る。

- 原因: 画面（`web/api.js`）の `API_VERSION` と、GAS（`gas/Code.gs`）の `API_VERSION` が違う。
- 利用者: 「再読み込み」を押す。
- 再読み込みしても出続ける場合（担当者）:
  - 画面だけ push して GAS をデプロイしていない → GAS を新バージョンでデプロイする。
  - GAS だけ新しくして画面を push していない → 画面を push する。
  - 両方そろえたのに出る → ブラウザのキャッシュ（「5. キャッシュ」）。
- 順番は「GAS を先 → 画面を後」です（[03](03_保守・更新手順.md)）。

## 3. GAS の権限・デプロイのエラー

| 症状 | 原因と対処 |
| :--- | :--- |
| GAS の URL を開くと Google のログイン画面が出る | 「アクセスできるユーザー」が「全員」になっていない。「デプロイを管理」で直す |
| 「アクセスできるユーザー」に「全員」が出ない | 大学の Google Workspace の管理者が外部への公開を制限している。（要確認：大学の情報システムの窓口に相談） |
| デプロイ・実行時に「承認が必要です」「権限を確認」と出る | 初回やスプレッドシートの読み書きの権限が変わったとき。「権限を確認」→ 自分のアカウント →「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」 |
| GAS を直したのに変わらない | 保存しただけで、新バージョンでデプロイしていない。「デプロイを管理」→ 鉛筆 →「新バージョン」→「デプロイ」 |
| 「新しいデプロイ」を作ってしまった | URL が変わっている。元のデプロイを新バージョンにするか、新しい URL を `web/config.js` に書く。使わないデプロイはアーカイブする |
| メニュー「予約システム」が出ない | スプレッドシートを再読み込みする。それでも出なければ Apps Script で `setup` を一度実行する |
| Google の利用上限に達した（実行数にエラーが出る） | GAS には、1日あたり・同時実行などの上限がある（要確認：Google の公表している上限 https://developers.google.com/apps-script/guides/services/quotas と実際の利用量）。多くは翌日に戻る |

## 4. パスワードの誤入力・ロック

| 画面の文言 | 意味 | 対処 |
| :--- | :--- | :--- |
| 「編集用パスワードが一致しません。」 | 予約の4桁が違う | 正しい4桁を入れる。忘れたら管理者が管理者モードで対応 |
| 「この予約には編集用パスワードが設定されています。編集用パスワードを入力してください。」 | 4桁が未入力 | 入力する |
| 「編集用パスワードの誤入力が続いたため、この予約は一時的に操作できません。10分ほど待ってから再度お試しください。」 | 同じ予約で5回続けて間違えた | 10分待つ。急ぐなら管理者モードで対応（管理用パスワードはこのロックを受けない） |
| 「管理用パスワードが一致しません。」 | 管理用パスワードが違う | 正しいパスワードを入れる |
| 「管理用パスワードの誤入力が続いたため、一時的に利用できません。10分ほど待ってから再度お試しください。」 | 管理用パスワードの誤入力が全体で10回に達した（誤入力のたびに10分の期限が延びる） | 間違えずに10分以上待つ。総当たりされている疑いがあれば、落ち着いてから管理用パスワードを変える |
| 「管理用パスワードが設定されていません。管理者に連絡してください。」 | スクリプトプロパティ `ADMIN_PASSWORD` がない | スプレッドシートのメニュー「予約システム > 管理用パスワードを設定」で設定する |
| 「管理者モードを終了しました（管理用パスワードが変更された可能性があります）。」 | 別の所で管理用パスワードが変えられた | 管理画面に新しいパスワードでログインし直す |
| 「閲覧パスワードを入力してください。」「閲覧パスワードが違います。」 | 予約表全体の閲覧制限が設定されている | 正しいパスワードを入れる。不要なら管理画面「パスワード」タブで空欄にして保存 |
| 「パスワードが違います。」（限定公開の入口） | 限定公開の部屋のパスワードが違う。全体で30回間違えると10分間は正しいパスワードでも通らない | 正しいパスワードで、必要なら10分待って試す |
| 「限定公開の部屋のパスワードが変更されたため、表示を終了しました。」 | 管理者がパスワードを変えた | 新しいパスワードを管理者から受け取り、入口の URL から入り直す |

## 5. キャッシュ（古い画面が出る）

- GitHub Pages の画面は、ブラウザに最大10分ほど残ることがあります。再読み込みしてください。
  - iPhone の Safari: アドレス欄の再読み込みボタン。直らなければ「設定 > Safari > 履歴と Web サイトデータを消去」（名前の自動入力・自分の予約も消えるので注意）。
  - パソコン: `⌘ + Shift + R`（Mac）／`Ctrl + Shift + R` または `Ctrl + F5`（Windows）。
- `config.js`・`api.js`・アイコンは、公開のたびに読み込み先に `?v=（コミットの先頭8文字）` が付くので、HTML が新しくなれば一緒に新しくなります。
- 予約データは画面側で3分間保持していますが、自動更新（1分ごと）やタイトル横の「○:○○ 更新」で取り直します。

## 6. 公開が反映されない（GitHub Actions）

1. リポジトリの「Actions」タブを開き、「GitHub Pages に公開」の最新の実行を見る。
   - 実行がない: push したのが `main` 以外のブランチか、`web/` と `.github/workflows/pages.yml` 以外しか変えていない。`main` に `web/` の変更が入っているか確かめる。必要なら「Run workflow」で手動実行する。
   - 赤い×（失敗）: 実行を開き、どの手順で失敗したかを見る。一時的な失敗なら「Re-run jobs」でやり直す。
   - 緑のチェック（成功）: 「5. キャッシュ」を確かめる。
2. 「Settings > Pages」の「Source」が「GitHub Actions」になっているか確かめる。
3. コマンドで確かめる場合:

   ```bash
   gh run list -R miyakyo-music/yoyaku -L 5
   gh run view <実行の番号> -R miyakyo-music/yoyaku --log-failed
   ```

## 7. 予約の操作でよく出る文言

| 文言 | 意味 |
| :--- | :--- |
| 「すでに存在する予約と時間が重複しています（…）。」 | 他の人が先に予約した。予約表が更新されるので選び直す |
| 「過去の時間帯は予約できません。」 | 終了時刻が過ぎている |
| 「定休日（○曜日）のため予約できません。」 | 「利用時間・制限」の定休日 |
| 「終日利用できません（理由）。」「○:○○〜○:○○ は利用できません（理由）。」 | 「休館・利用停止」に登録されている |
| 「予約できるのは○日先までです。」 | 予約受付期間の制限（管理者は受けない） |
| 「1回に予約できるのは○時間までです。」 | 最大予約時間の制限（管理者は受けない） |
| 「時刻は○分単位で指定してください。」 | 予約単位に合っていない |
| 「（部屋名） は管理者のみ予約できます（管理用パスワードが必要です）。」 | 予約制限が「管理者のみ」の部屋 |
| 「（部屋名） は現在使用停止中です。」 | 予約制限が「使用停止」の部屋 |
| 「くり返し予約・複数部屋の同時予約には管理用パスワードが必要です。」 | 「まとめて予約は管理者のみ」が有効 |
| 「予約できない日・部屋が含まれています。」 | まとめて予約の一部が重複などで不可。「予約できる○件だけ予約」で残りを登録できる |
| 「この予約は既に取り消されているか、存在しません。」 | 他の人が先に取り消した（または限定公開の部屋で、見る権限がない） |
| 「終了した予約は変更できません。」 | 管理者以外は終わった予約を変えられない |
| 「学籍番号/所属・氏名・備考の先頭に「= + - @」は使用できません。」 | 数式として悪用されないための制限 |
| 「現在、報告が集中しています。しばらくしてから再度お試しください。」 | 不具合報告が10分間に全体で30件を超えた |
