# 練習室予約システム 仕様書

この文書は、今の動きをまとめたものです。**動きを変えたときは、同じコミットでこの文書も書き直します。**
数値（上限・時間）は、コードの定数と一致させています（定数の場所は各節に記載）。

- 対象の版: v0.4.4-beta（`web/api.js` の `APP_VERSION`）
- 予約表: https://miyakyo-music.github.io/yoyaku/
- 管理画面: https://miyakyo-music.github.io/yoyaku/admin.html

## 1. 構成

| 部分 | 置き場所 | 公開・反映のしかた |
| :--- | :--- | :--- |
| 予約表の画面 | `web/index.html`（CSS・JS も同じファイル） | `main` に push すると GitHub Actions が GitHub Pages に公開（数分） |
| 管理画面 | `web/admin.html` | 同上 |
| プライバシーポリシー | `web/privacy.html` | 同上 |

| 接続先の GAS の URL | `web/config.js` | 同上 |
| サーバー（API） | `gas/Code.gs` | Apps Script エディタに貼り付けて「デプロイを管理」→ 新しいバージョン（手作業。URL は変わらない） |
| データ | Google スプレッドシート（6枚のシート。5章） | GAS が読み書き。管理者は直接編集してもよい |

画面と GAS の約束の版は `API_VERSION`（`web/api.js` と `gas/Code.gs` の両方。今は 1）。ずれると画面に再読み込みの案内を出す。

## 2. 予約表（`web/index.html`）

### 2.1 上部

- **試験運用中の帯**: 版の名前に `beta` を含む間だけ出す。「不具合を報告」ボタン付き。
- **タイトル**（設定「予約表のタイトル」）。
- **管理（歯車）**: 管理画面へのリンク。管理者モードでは、未対応・対応中の不具合報告の件数を赤いバッジで出す。
- **更新**: 「↻ 17:40 更新」の表示そのものがボタン。押すと最新を取得。読み込み中は ↻ の代わりに iOS と同じ8本線の「くるくる」が回る（大きさは偶数の 16px / スマホ 18px にして、回転の軸がぶれないようにする）。スマホでは ↻ のアイコンだけ。
- **「管理者」「限定公開」の札**: 更新ボタンの右。押すとそのモードを終了し、ページを読み込み直す。
- **お知らせ**: 設定「お知らせ」が空でなければ出す。種類「通常」は青、「重要」は赤。管理者モードでは、押すとその場で文と種類を書き換えて保存できる（`adminSetNotice`）。書き換え中は自動更新で消さない。
- **自分の予約**: この端末で作った今日以降の予約の一覧。押すとその日の予約表へ移る。
- **新規予約**: PC（幅 601px 以上）は上部の「＋ 新規予約」。スマホ（幅 600px 以下）は右下に浮かぶ丸い「＋」ボタン。
- **表示の切り替え**（一覧／部屋別／カレンダー）: 白いつまみが選んだ方へ滑る。
- **日付の移動**: 「‹」「›」（一覧は1日、部屋別・カレンダーは1か月）、日付欄（押すとカレンダー）、「今日」。「今日」の文字は、今日（カレンダーでは今月）を表示しているときだけ青、それ以外は黒。
- **設備の絞り込み**（一覧のみ）、**空室**ボタン（一覧で今日のときのみ有効）、**凡例**（PC のみ）。

### 2.2 一覧（1日・全部屋）

- 行 = 部屋（設備で絞り込み可）。部屋名の列と時刻の見出しは貼り付いて動かない。
- **空室ランプ**（今日の一覧のときだけ、部屋名の前の点。左に 2px あける）:
  - 緑 = 空き / 黄 = 30分以内に予約あり / 赤 = 使用中（信号に見立てる） / 灰 = 利用時間外・使用停止・休館中
  - 見た目は控えめにする: 7px の少しくすんだ点に、輪郭のないごく弱いぼかし。部屋の大半を占める「空き」の緑は薄め（不透明度 .7）にして、赤と黄が少し目に入るようにする。
  - 判定は画面側の今の時刻と、画面に読み込んでいる予約・休館から（`lampOf`）。
- 現在時刻の赤い縦線（半透明）、過ぎた時間は灰色、休館・利用停止は斜線、使用停止の部屋は行全体が灰色。
- 予約の帯: オレンジ = 予約済み、青 = この端末の予約、点線 = 送信中、薄い = 終了済み。左端に丸い縦線。帯は行の上下に 1px ずつだけ余白をとり、行の高さをほぼ使い切る（仮の点線の帯も同じ）。名前と学籍番号は、横にスクロールしても見えている部分の左端に残る。
- 部屋名を押すと、その部屋の「部屋別」へ。
- **空室**: 今から30分以上（閉館が近ければ閉館まで）空いている部屋だけにし、「○時まで空き」を添える。

### 2.3 部屋別・カレンダー

- **部屋別**: 1部屋の、選んだ日から1か月分（例: 10/8〜11/7）を日ごとの行で表示。日付を押すとその日の一覧へ。
- **カレンダー**: 月表示。部屋を選べばその部屋の予約、「すべての部屋」なら日ごとの件数と自分の予約数。日付を押すとその日の一覧へ。

### 2.4 予約の作り方

| 端末 | 操作 |
| :--- | :--- |
| PC | 空いている所をクリック → 予約画面。ドラッグで時間を指定。 |
| スマホ | 空いている所をタップ → 「＋予約」の帯（5秒たつと消える）→ 帯をもう一度タップで予約画面。長押し（0.4秒）してからなぞると時間を指定。スクロール中・直後（0.3秒）のタップは無視。 |
| 共通 | 「＋ 新規予約」／右下の「＋」から、部屋・日付・時刻を指定。一覧で設備を絞り込んでいるときは、部屋の選択肢も同じ設備に絞る。一覧の表示から開いたときは、まず部屋のボタン（部屋名と設備の2段・中央寄せ、幅に応じて3列ほど。設備ごとに表のタグと同じ色をごく薄く敷く: UP=オレンジ、GP=緑、電子=青）を広げて見せ、押すといつもの選択欄に戻って氏名の欄へ進む。部屋を選ぶまで仮の帯は出さず、そのまま「予約確定」を押すと「部屋を選んでください」。表から開いたとき・部屋別／カレンダー表示・変更時は広げない。 |

- 時間軸の幅は、ピンチ（スマホ）や Ctrl＋ホイール（PC）で広げ縮めできる。既定の1時間の幅は PC 96px、スマホ 62px（画面が広ければ画面いっぱいまで広げる）。変えている間は左上に「（幅を）リセット」。
- 予約画面を開いている間は、選んだ部屋・時間に点線の仮の帯を出す。新規予約の点線を出し始めたら、予約の帯に残っていた青い枠（フォーカス）は外す。

### 2.5 予約画面

- 入力: 部屋、日付、開始・終了（予約単位ごと）、氏名／団体名（必須・50文字まで）、学籍番号／所属（任意・30文字まで）、備考（任意・100文字まで）、編集用パスワード（任意・4桁の数字）。
- 選択欄（部屋・開始・終了）の矢印は、端末の標準の矢印を使わず、どの欄も右端から 12px の位置に同じ矢印を描く（部屋の欄と時刻の欄で位置をそろえる）。
- 必須の欄（氏名／団体名、変更時の編集用パスワード、まとめて予約時の管理用パスワード、不具合報告の内容）は、見出しの右に赤い「*」を付ける（Google フォームの必須の質問と同じ印）。印のない欄は任意（見出しに「（任意）」とは書かない）。
- 先頭が「= + - @」の入力は受け付けない（スプレッドシートの数式として悪用されないように）。
- 編集用パスワードの欄は、iPhone などのパスワード管理（キーチェーン）が開かないよう、`type="text"` に `-webkit-text-security: disc` で伏せ字にし、`autocomplete="one-time-code"` を付ける（1Password などの拡張機能にも無視の印）。
- 氏名・学籍番号・編集用パスワードは、予約確定時にこの端末に覚え、次回から自動で入る。名前が入っていればキーボードを出さない。
- **まとめて予約**（管理者モード、または設定で全員に許可したとき）: 他の部屋も同時に予約（同じ名前の部屋はまとめて選べる）、くり返し予約（毎週・隔週・毎日、最終日まで）。最大件数は設定「まとめて予約の最大件数」（部屋数×日数）。予約できない日があるときは一覧を出し、「予約できる分だけ予約」を選べる。
- キーボードの改行キーで次の欄へ進み、最後の欄ではキーボードを閉じる（改行キーでは予約を確定しない。うっかり予約を防ぐため）。
- 下端の「戻る」「予約確定」は小窓の枠の一部として下端に固定し、その上の入力欄だけがスクロールする（JS が起動時に、`.actions` より前の中身を `.dlg-main` に包む。以前の sticky による貼り付けは、開く動きの途中で Safari が帯を遅れて動かしカクついたためやめた）。小窓の中のボタンは、ぼかしを重ねない。キーボードが出ている間に隠れる問題は未解決（6章）。
- **小窓（予約画面・詳細・自分の予約など、すべてのダイアログ）の開き方**: 直前（1.5秒以内）に押した位置から広がって開き（0.5秒、ごくわずかに行き過ぎて止まる）、閉じるとその位置へ縮んで戻る（0.2秒）。押した位置がないとき（キーボード操作など）は中央から。後ろを暗くする幕は薄く出入りする。古い Safari（iOS 17.4 以前など `@starting-style` 非対応）では動かず、ぱっと開く。端末の「視差効果を減らす」がオンなら、動かさずに薄く出るだけ。

### 2.6 詳細・変更・取消

- 予約の帯を押すと詳細（部屋・日付・時間・予約者・備考）。編集用パスワードが付いた予約は、その4桁を入れて「変更」「取消」。管理者モードでは不要。
- 終了した予約は変更・取消できない（管理者を除く）。「管理者のみ」の部屋の予約は、管理者だけが変更・取消できる。
- **まとめ予約の1件**:
  - 取消: 「この日以降の分（全部屋）をまとめて取り消す」を選べる。
  - 変更: 「この日以降の分もまとめて変更する」を選べる。まとめて変わるのは時間・氏名・学籍番号・備考で、日付と部屋はそれぞれのまま。1件でも重複などで変更できなければ、どれも変更せず、変更できない日の一覧を出す。
- PC では、予約の帯にマウスを0.3秒乗せると詳細カードが出て、マウスについて動く。画面の端では反対側に回る。

### 2.7 表示の速さと自動更新

| 仕組み | 内容 | 定数 |
| :--- | :--- | :--- |
| 前回の表示 | 開いた直後、前回と同じ表示なら端末に覚えた予約表をすぐ出し、裏で最新に差し替える（24時間以内のもの。閲覧パスワードが必要な予約表では覚えない） | `LS.snapshot` |
| 画面側の覚え | 一度取得した期間は3分間、通信せずに表示 | `CACHE_TTL_MS` |
| 先読み | 一覧は前日・翌日、部屋別・カレンダーは前月・翌月を裏で取得 | `prefetchNext` |
| 先に反映 | 新規予約（1件）・変更（1件）・取消は、サーバーの返事を待たずに画面へ反映し、失敗したら元に戻して画面を開き直す | `createOptimistic` ほか |
| 自動更新 | 60秒ごと。ページが裏にあるとき・操作中（触れている、ダイアログが開いている、最後の操作から3秒以内）はしない。中身が変わっていなければ描き直さない | `AUTO_REFRESH_MS`, `IDLE_MS` |
| 切り替えの動き | 「‹」「›」で切り替えたとき、表を進む向きから軽くすべり込ませる（動きを減らす設定では出さない） | `state.slide` |
| サーバー側の覚え | 2.4節ではなく4.3節 | — |

### 2.8 限定公開の部屋・閲覧パスワード

- 部屋の予約制限が「限定公開」の部屋（演習室など）は、限定公開のパスワードを入れた端末と管理者にだけ、部屋も予約も休館も返す。一般の利用者には部屋があること自体を出さない（サーバーが返さない）。
- 入口: `…/yoyaku/?limited`。パスワードは端末に覚える。この URL から開いたときだけ、設備の絞り込みを限定公開の部屋の設備区分に合わせる（端末には記憶しない）。
- パスワードが変わると、覚えていた端末でも表示を終了する。
- 閲覧パスワード（設定）を決めると、予約表を見る・予約するのにパスワードが必要になる（端末に覚える）。通常は使わない。

### 2.9 不具合報告

- フッタと試験運用中の帯の「不具合を報告」から。内容（2000文字まで）と連絡先（任意）に、端末・画面の情報（版、ブラウザ、画面の大きさ、表示中の画面など。パスワードは含まない）を添えて送る。
- 全体で10分に30件まで。

### 2.10 画面幅ごとの配置

| 幅 | 配置 |
| :--- | :--- |
| 1200px 以上 | PC。上部1段目にタイトル・お知らせ・ボタン |
| 601〜1199px | PC のまま、お知らせは2段目に。2段目の余白と凡例を少し詰める（iPad 12.9 インチ縦の 1024px で1行に収まる） |
| 600px 以下 | スマホ。右下の「＋」、アイコンだけのボタン、決まった段組み、部屋名の列と時間を細く |
| 380px 以下 | ボタンの余白をさらに詰める |

画面の最小幅は 360px（それより狭いと画面全体を横にスクロール）。iPhone の Safari では、予約表は下のバーの上端までの表示（ページ全体ではなく表だけがスクロールする作りのため）。

### 2.11 端末に保存するもの（localStorage / sessionStorage）

| キー | 中身 |
| :--- | :--- |
| `prr.profile` | 氏名・学籍番号・編集用パスワード |
| `prr.myReservations` | この端末で作った予約の ID と日付（7日より前は消す） |
| `prr.view` / `prr.room` / `prr.equipFilter` / `prr.zoom` | 表示の種類・部屋・設備の絞り込み・時間軸の拡大率 |
| `prr.viewKey` / `prr.limitedKey` | 閲覧パスワード・限定公開のパスワード |
| `prr.snapshot` | 前回表示した予約表 |
| `prr.adminDevice` | 管理画面にログインしたことのある端末の印（3.2節） |
| `prr.fromAdmin`（sessionStorage） | 管理画面を開いた印。予約表に戻ったときに前回の表を使わず最新を読み込ませ、読んだら消す |
| `prr.adminPw`（sessionStorage） | 管理用パスワード。そのタブで管理画面にログインしている間は、予約表も管理者モード |

## 3. 管理画面（`web/admin.html`）

### 3.1 タブ

| タブ | できること |
| :--- | :--- |
| 練習室 | 部屋の追加・削除・名前・特徴タグ（「・」区切り、例: 大・GP）・設備区分・予約制限（なし／管理者のみ／限定公開／使用停止）・備考。並べ替えは左端の番号をつまんでドラッグ（↑↓ のボタンは廃止）。スマホでは部屋ごとに畳み、押した部屋だけ開く。今日以降の予約が残る部屋は削除できない |
| 利用時間・制限 | タイトル、お知らせと種類、利用開始・終了時刻、予約単位、1回の最大予約時間、予約受付期間、定休日、まとめて予約の最大件数と管理者限定 |
| 休館・利用停止 | 日付・部屋（空欄=全室）・時間帯（空欄=終日）・理由の登録と削除 |
| パスワード | 限定公開の部屋のパスワード（6文字以上）と入口の URL のコピー、閲覧パスワード（畳んである）、管理用パスワードの変更 |
| 不具合報告 | 報告の一覧と状態（未対応／対応中／対応済み／対応しない）。未対応・対応中の件数をタブにバッジで出す |

- このタブで一度ログインしていれば、開いたときに自動でログインし直す。確かめている間はパスワード欄を出さず「ログイン状態を確認しています…」と出す（入力の途中で画面が切り替わらないように）。
- 管理画面を開くと、このタブに印（sessionStorage の `prr.fromAdmin`）を置く。予約表は起動時にこの印があれば、前回の表を使わず最新を読み込む。ブラウザの「戻る」で古い画面がそのまま出たときは、ページごと読み直す（部屋・設定の変更をすぐ反映するため）。
- タブも白いつまみが滑って移動する。
- 「データベース」ボタンで、予約のスプレッドシートを開く（共有されている Google アカウントのみ）。
- すべてのパスワード欄に「表示」ボタン。ダイアログを閉じると伏せ字に戻す。
- 選択欄（予約制限・お知らせの種類・休館の部屋・不具合の状態など）の矢印は、右端から 12px の位置に描く（標準の矢印は欄が広いと右端に寄りすぎるため）。時刻・数値の欄は 7px。

### 3.2 管理用パスワードの誤入力

- 誤入力は全体で数え、10回で10分間受け付けない。
- ただし、管理画面にログインできた端末には印（`adminDevice`）を渡して覚え（最大30台、古い順に忘れる）、その端末の誤入力は端末ごとに数える。誰かが全体をロックさせても、いつもの端末からは入れる。
- 予約の編集用パスワードの欄に4桁の数字以外を入れた場合は、管理用パスワードとして照合し、外れは上の回数に数える。

## 4. サーバー（`gas/Code.gs`）

### 4.1 API（`doPost` の `action`。`API` に登録したものだけ呼べる）

| 処理 | 内容 |
| :--- | :--- |
| `getSchedule` | 期間（最長42日）の予約・休館・部屋・設定 |
| `getReservationsByIds` | 予約 ID を指定して取得（自分の予約） |
| `createReservation` / `createBulkReservations` | 予約／まとめて予約 |
| `updateReservation` | 変更（`scope: 'following'` でまとめて変更） |
| `cancelReservation` | 取消（`scope: 'following'` でこの日以降をまとめて） |
| `submitBugReport` | 不具合報告 |
| `adminGetData` ほか `admin*` | 管理用（管理用パスワードが必要） |

### 4.2 上限と回数制限（`SYSTEM` ほか）

| 対象 | 上限 |
| :--- | :--- |
| 予約の登録・変更・取消・まとめて予約 | 全体で毎分30件（`MAX_WRITES_PER_MINUTE`）。超えると「予約の操作が集中しています」 |
| 編集用パスワードの誤入力 | 同じ予約で5回 → その予約を10分操作不可 |
| 管理用パスワードの誤入力 | 全体で10回 → 10分（ログインしたことのある端末は端末ごと。3.2節） |
| 限定公開のパスワードの誤入力 | 全体で30回 → 10分 |
| 不具合報告 | 全体で10分に30件 |
| 同時の書き込み | ScriptLock で1件ずつ。10秒待っても順番が来なければ「アクセスが集中しています」 |

### 4.3 サーバー側の覚え（CacheService）

- `getSchedule` は、同じ期間・同じ見え方（限定公開の有無）の結果を、予約・設定が変わるまで（最長60秒）覚えて返す（100KB 未満のときのみ）。予約・設定を変える処理（`withLock_` の中）が成功すると版（`schedVer`）が変わり、覚えていた分は使わない。
- スクリプトプロパティ（`ADMIN_PASSWORD`・`SPREADSHEET_ID`・`ADMIN_DEVICES`）は、読み出しが1日5万回までなので10分覚えておく（`prop_`）。書き換えは `setProp_` を通す。GAS の画面でプロパティを直接書き換えた場合、反映に最長10分かかる。

### 4.4 スプレッドシートのメニュー（「予約システム」）

初期セットアップ / 前年度の予約をアーカイブ / 管理用パスワードを設定 ほか（`onOpen`）。

## 6. 既知の制限・未解決

- **iPhone でキーボードを開くと「予約確定」が隠れる**: キーボードの上のバー（∧ ∨ ✓）に重なる。試して撤回した方法: ダイアログを見えている範囲に縮める（入力欄がずれる）、帯をキーボードの上に持ち上げる（Safari の動きとぶつかる）、キーボードの高さの余白を足す（効果がなく、iPad の不具合報告などでダイアログの下に大きな空白が出た）。改善点として残している。
- **Safari の下のバーの裏まで表を伸ばせない**: 表だけがスクロールする作りのため。ページ全体をスクロールさせる作りには変えない方針（縦横に動く表と相性が悪い）。
- **光の屈折**: 上部の帯・ダイアログ・詳細カードの縁の屈折は、Chrome・Edge だけで出る（SVG フィルタ）。Safari はぼかしのみ。
- **予約者の名前と学籍番号は、URL を知っている人なら誰でも見られる**（りざぶ郎と同じ考え方）。
- iPhone が「学籍番号／所属」の欄に保存済みのパスワードを候補として出すことがある。

## 7. 見た目の決まり

- 端末の設定に合わせて、ライトモードとダークモードを自動で切り替える（予約表・管理画面・プライバシーポリシーのすべて）。URL に `?dark` を付けると常にダーク、`?light` を付けると常にライト（確認用）。読み込み時に白く光らないよう、`<head>` の中で `html.dark` を付ける。
- iOS 風の控えめなガラス（半透明＋ぼかし＋縁の光）。ボタン・選択欄は角丸 11px、ダイアログ 22px。主役のボタン（新規予約・予約確定など）だけ青（#007aff）。
- ダークモード（iOS の設定アプリに合わせる）: 背景は黒、表・カードは #1c1c1e、ふつうのボタンは上端だけかすかに光る平らな濃い灰色（#262628）。青いボタンは少し明るい平らな青（#3b8ff5）に縁がかすかに光る輪郭（iOS の決定ボタン風）。ダイアログと PC の詳細カードは、後ろの表がぼけて透けるすりガラス（灰色 52〜55% ＋ぼかし 24〜30px）。色は各ファイルの「ダークモード」の層（`html.dark` で始まる指定）にまとめてある。
- 予約の帯: 予約済み = オレンジ（#ff9500 系、ダークでは #ff9f0a 系）、この端末の予約 = 青（#007aff 系、ダークでは #0a84ff 系）。
- ぼかしに対応していない環境・「透明度を下げる」設定では、透けない面にする。
- デザイン変更の前の版はタグ `v0.3.3-beta` に保存。
