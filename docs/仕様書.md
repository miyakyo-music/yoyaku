## 2. 予約表（`web/index.html`）

### 2.1 上部

- **試験運用中の帯**: 版の名前に `beta` を含む間だけ出す。「不具合を報告」ボタン付き。
- **タイトル**（設定「予約表のタイトル」）。
- **管理（歯車）**: 管理画面へのリンク。管理者モードでは、未対応・対応中の不具合報告の件数を赤いバッジで出す。
- **更新**: 「↻ 17:40 更新」の表示そのものがボタン。押すと最新を取得。読み込み中は ↻ の代わりに iOS と同じ8本線の「くるくる」が回る（大きさは偶数の 16px / スマホ 18px にして、回転の軸がぶれないようにする）。スマホでは ↻ のアイコンだけ。
- **予約の検索（虫眼鏡）**: 更新ボタンの右。押すと検索の小窓が開き、氏名・団体名・学籍番号／所属・備考・部屋名から探す（入力するたびに絞り込む。全角・半角、大文字・小文字、ひらがな・カタカナ、空白の違いは区別しない。漢字を読み仮名で探すことはできない）。探す範囲は今日から設定「予約受付期間」の日数先まで（30〜180日に収める）で、予約表と同じ読み方（高速キャッシュ → GAS）で42日ずつ読む。今日の終わった予約は出さない。一致した所に黄色の印。押すとその日の一覧へ移り、詳細を開く（最大200件）。
- **「管理者」「限定公開」の札**: 検索ボタンの右。押すとそのモードを終了し、ページを読み込み直す。
- **お知らせ**: 設定「お知らせ」が空でなければ出す。種類「通常」は青、「重要」は赤。管理者モードでは、押すとその場で文と種類を書き換えて保存できる（`adminSetNotice`）。書き換え中は自動更新で消さない。
- **自分の予約**: 「予約」と「練習時間」の切り替え。
  - 予約: この端末で作った今日以降の予約の一覧。押すとその日の予約表へ移る。
  - 練習時間（説明の文は出さない）: この端末で予約した分の、今週（月〜日）・今月・今年度（4月〜3月）の合計時間と回数、部屋ごと（多い順に6つ）、曜日ごと（月曜はじまり）。終わった予約を「練習した時間」とし、これからの分は「このあと予定」として添える。端末の記録 `prr.myHistory` の予約 ID をサーバーから読み直して数えるので、取り消された予約は数えない（300件ずつ `getReservationsByIds`）。
- **新規予約**: PC（幅 601px 以上）は上部の「＋ 新規予約」。スマホ（幅 600px 以下）は右下に浮かぶ丸い「＋」ボタン。表の下のフッター（版の表示など）が見えてきたら、その分だけ持ち上がり、表の下端の上に乗る（フッターに重ならない）。
- **表示の切り替え**（一覧／部屋別／カレンダー）: 白いつまみが選んだ方へ滑る。
- **日付の移動**: 「‹」「›」（一覧は1日、部屋別・カレンダーは1か月）、日付欄（押すとカレンダー）、「今日」。「今日」の文字は、今日（カレンダーでは今月）を表示しているときだけ青、それ以外は黒。
- **設備の絞り込み**（一覧のみ。「★ お気に入り」で、お気に入りの練習室だけにできる。「★ お気に入りを選ぶ…」で部屋のボタンの一覧が開き、押して選ぶ。同じ名前の部屋は「全◯室」でまとめて選べる。選び終わると「★ お気に入り」で絞り込む。1つも選ばなければ元の絞り込みに戻す。新規予約の部屋の選択肢も同じく絞る）、**空室**ボタン（一覧で今日のときのみ有効）、**凡例**（PC のみ）。

### 2.2 一覧（1日・全部屋）

- 行 = 部屋（設備で絞り込み可）。部屋名の列と時刻の見出しは貼り付いて動かない。
- **空室の帯**（今日の一覧のときだけ、部屋名の欄の左端の細い縦の帯。予約の帯の左の縦線と同じ形。部屋名とタグはその右で左端をそろえる）:
  - 緑 = 空き / 黄 = 30分以内に予約あり / 赤 = 使用中（信号に見立てる） / 灰 = 利用時間外・使用停止・休館中
  - 色は控えめにする（少しくすんだ色・ごく弱いぼかし）。部屋の大半を占める「空き」の緑は薄め（不透明度 .7）。
  - 判定は画面側の今の時刻と、画面に読み込んでいる予約・休館から（`lampOf`）。
- 現在時刻の赤い縦線（半透明）、過ぎた時間は灰色、休館・利用停止は斜線、使用停止の部屋は行全体が灰色。
- 予約の帯: オレンジ = 予約済み、青 = この端末の予約、点線 = 送信中、薄い = 終了済み。左端に丸い縦線。押した予約の青い枠は、帯の色の部分の内側に描く（色の部分とぴったり重なる）。行の時間軸の欄は部屋名の欄と同じ高さまで伸びる。帯は行の上下に 1px ずつだけ余白をとり、行の高さをほぼ使い切る（仮の点線の帯も同じ）。名前と学籍番号は、横にスクロールしても見えている部分の左端に残る。
- 部屋名を押すと、その部屋の「部屋別」へ。
- **空室**: 今から30分以上（閉館が近ければ閉館まで）空いている部屋だけにし、「○時まで空き」を添える。

### 2.3 部屋別・カレンダー

- **部屋別**: 1部屋の、選んだ日から1か月分（例: 10/8〜11/7）を日ごとの行で表示。日付を押すとその日の一覧へ。
- **カレンダー**: 月表示。部屋を選べばその部屋の予約、「すべての部屋」なら日ごとの件数と自分の予約数。日付を押すとその日の一覧へ。

### 2.4 予約の作り方

| 端末 | 操作 |
| :--- | :--- |
| PC | 空いている所をクリック → 予約画面。ドラッグで時間を指定。予約の帯をつかんで動かすと、その予約を別の時間・部屋（部屋別では日）へ動かせる（下の「予約を動かす」）。 |
| スマホ | 空いている所をタップ → 「＋予約」の帯（5秒たつと消える）→ 帯をもう一度タップで予約画面。長押し（0.4秒）してからなぞると時間を指定。予約の帯を長押しすると持ち上がり、そのまま指を動かして別の時間・部屋へ動かせる。スクロール中・直後（0.3秒）のタップは無視。 |
| 共通 | 「＋ 新規予約」／右下の「＋」から、部屋・日付・時刻を指定。一覧で設備を絞り込んでいるときは、部屋の選択肢も同じ設備に絞る。一覧の表示から開いたときは、まず部屋のボタン（部屋名と設備の2段・中央寄せ、幅に応じて3列ほど。設備ごとに表のタグと同じ色をごく薄く敷く: UP=オレンジ、GP=緑、電子=青）を広げて見せ、押すといつもの選択欄に戻って氏名の欄へ進む。部屋を選ぶまで仮の帯は出さず、そのまま「予約確定」を押すと「部屋を選んでください」。表から開いたとき・部屋別／カレンダー表示・変更時は広げない。 |

- 時間軸の幅は、ピンチ（スマホ）や Ctrl＋ホイール（PC）で広げ縮めできる。既定の1時間の幅は PC 96px、スマホ 62px（画面が広ければ画面いっぱいまで広げる）。変えている間は左上に「（幅を）リセット」。
- **ドラッグの刻み**（新規予約）: 指の太さで「17:00 のつもりが 17:05」とならないよう、ドラッグで選ぶ開始時刻は10分刻み（予約単位で割り切れなければ予約単位）のいちばん近い区切りに吸い付く（`dragStartStep`）。終了時刻は予約単位で決まる。左へ引いたときは、押した所が終了（予約単位で丸める）、指を離した所が開始（10分刻み）になる。細かい時刻は予約画面のホイールで直す。
- **予約を動かす**: 帯の影が指（マウス）について動き、横は時刻（予約単位の刻み。つかんだ所が指の下に残る）、縦は行（一覧は部屋、部屋別は日付）が変わる。重なり・休館・過去・使用停止の所では影が赤くなる。利用時間は元のまま（終了は開始＋元の長さ）。離すと、新しい部屋・日・時刻を入れた「予約の変更」画面を開き（最初からこの値で開く。開いてから時刻の欄を回し直すと、iPhone で一部が元に戻り時間が延びたため）、「変更を保存」で確定する。時刻の欄に触れずに保存したときは、念のため長さを元の利用時間にそろえて送る（うっかり動かしても確定しない。編集用パスワードの確認も今まで通り。この端末で作った予約は覚えている4桁を入れておく）。動かせないのは、終わった予約・送信中の予約・管理者モードでないときの「管理者のみ」の部屋の予約。赤い所で離すと「その時間には動かせません」。PC は Esc で取りやめ。
- 予約画面を開いている間は、選んだ部屋・時間に点線の仮の帯を出す。新規予約の点線を出し始めたら、予約の帯に残っていた青い枠（フォーカス）は外す。

### 2.5 予約画面

- 入力: 部屋、日付、開始・終了（予約単位ごと）、氏名／団体名（必須・50文字まで）、学籍番号／所属（任意・30文字まで）、備考（任意・100文字まで）、編集用パスワード（任意・4桁の数字）。
- 「部屋」と「日付」は、横幅が足りれば1行に並べ（1つ 140px 以上取れるとき。スマホでも並ぶ）、足りなければ縦に積む（`.room-date`）。
- **開始・終了の時刻はホイールで選ぶ**（どの端末でも同じ）。「時」「分」それぞれを指で上下に回すと、真ん中の帯の数字でカチッと止まる。PC はマウスのホイール・つかんで上下にドラッグ・数字を押す・↑↓キーでも選べる。見える段の数は画面の高さで変わる（高さ 760px 以下は3段、それより高いと5段。CSS の `--wheel-rows`）。端の段は傾けて小さくなる分、円筒に巻いた位置まで真ん中へ寄せ、段の間が端だけ空いて見えないようにする。もとの選択欄（`bStartH` など）は隠してデータの入れ物として残し、ホイールを回すとその値を変えて change を送る（`makeWheel`）。予約画面が閉じている間はホイールを回せないので、開いてから値に合わせ直す。合わせ直している最中は、読み取った位置で値を書き戻さない（小窓が開く動きの最中は指定した位置へすぐに動かず、古い位置を読んで値が元に戻ることがあった。利用者がホイールに触れたら解除）。
- 選択欄（部屋・開始・終了）の矢印は、端末の標準の矢印を使わず、どの欄も右端から 12px の位置に同じ矢印を描く（部屋の欄と時刻の欄で位置をそろえる）。
- 必須の欄（氏名／団体名、変更時の編集用パスワード、まとめて予約時の管理用パスワード、不具合報告の内容）は、見出しの右に赤い「*」を付ける（Google フォームの必須の質問と同じ印）。印のない欄は任意（見出しに「（任意）」とは書かない）。
- 先頭が「= + - @」の入力は受け付けない（スプレッドシートの数式として悪用されないように）。
- 編集用パスワードの欄は、iPhone などのパスワード管理（キーチェーン）が開かないよう、`type="text"` に `-webkit-text-security: disc` で伏せ字にし、`autocomplete="one-time-code"` を付ける（1Password などの拡張機能にも無視の印）。
- 氏名・学籍番号・編集用パスワードは、予約確定時にこの端末に覚え、次回から自動で入る。名前が入っていればキーボードを出さない。
- **まとめて予約**（管理者モード、または設定で全員に許可したとき）: 他の部屋も同時に予約（新規予約の部屋の一覧を小さくしたボタンで選ぶ。押すと青くなり、もう一度押すと外れる。上で選んだ部屋は外せない。同じ名前の部屋は先頭の「全◯室」でまとめて選べる）、くり返し予約（毎週・隔週・毎日、最終日まで。最終日の欄も日付の欄と同じく曜日付きで見せる）。最大件数は設定「まとめて予約の最大件数」（部屋数×日数）。予約できない日があるときは一覧を出し、「予約できる分だけ予約」を選べる。
- **重要な予定の色**: 管理者モードか、限定公開に入っているときだけ、予約画面に「重要な予定の色」（なし・赤・紫・緑）が出る。色を付けた予約は、予約表の帯（とカレンダー表示の行）がその色になり、文字が太くなる（「この端末の予約」の青より優先）。GAS でも、管理者か限定公開のパスワードを持つ人の指定だけを受け付け、ほかの人が送った色は無視する。一般の人が色付きの予約を変更しても、色はそのまま残る。予約台帳の13列目「色」（`red` / `purple` / `green` / 空）。
- キーボードの改行キーで次の欄へ進み、最後の欄ではキーボードを閉じる（改行キーでは予約を確定しない。うっかり予約を防ぐため）。
- 下端の「戻る」「予約確定」は小窓の枠の一部として下端に固定し、その上の入力欄だけがスクロールする（JS が起動時に、`.actions` より前の中身を `.dlg-main` に包む。以前の sticky による貼り付けは、開く動きの途中で Safari が帯を遅れて動かしカクついたためやめた）。小窓の中のボタンは、ぼかしを重ねない。キーボードが出ている間に隠れる問題は未解決（6章）。
- **小窓（予約画面・詳細・自分の予約など、すべてのダイアログ）の開き方**: 直前（1.5秒以内）に押した位置から広がって開き（0.5秒、ごくわずかに行き過ぎて止まる）、閉じるとその位置へ縮んで戻る（0.2秒）。押した位置がないとき（キーボード操作など）は中央から。後ろを暗くする幕は薄く出入りする。古い Safari（iOS 17.4 以前など `@starting-style` 非対応）では動かず、ぱっと開く。端末の「視差効果を減らす」がオンなら、動かさずに薄く出るだけ。
- **帯と小窓をつなぐ動き（View Transitions）**: 予約の帯を押すと、その帯が形を変えながら予約の詳細になり、「閉じる」・幕の外・Esc で閉じると帯へ縮んで戻る。ドラッグや空き枠の仮の帯から開く予約画面も同じ。予約確定・変更の保存では、予約画面が新しい帯へ縮んで収まる。広がるのはすりガラスのカード（ぼかしだけ。色と影は小窓の写しが持つので、終わったときの本物の小窓と見え方がそろう。ぼかしの強さも小窓と同じで、Chrome など屈折ありの環境は 5px）で、中身は拡大・縮小しない（帯の文字はすぐ消え、小窓の中身は本来の大きさのまま、カードが広がるにつれて見えてくる。写しを引き伸ばすと文字まで大きくせり出して見えたため、2026-10-10 に変更）。0.46秒。もとの帯が画面に見えていないとき、View Transitions 非対応の端末（iOS 17 以前など）、「視差効果を減らす」がオンの端末では、上の開き方のまま。`web/index.js` の `morph()`。

### 2.6 詳細・変更・取消

- **カレンダーに追加**: 予約の詳細の見出しの右のボタン（終わった予約には出さない）。Android は Google カレンダーの追加画面を開く。それ以外は高速キャッシュの `/ics`（`cache/worker.js`）の URL を開き、iPhone の Safari ではダウンロードを挟まずに「カレンダーに追加」の画面が出る（開始15分前に知らせる）。高速キャッシュを使っていないときは、画面でカレンダーのファイル（.ics）を作って保存させる。カレンダーに入れるのは「部屋の名前の予約」（例: 練習室1の予約。設備のかっこ書きは付けない）・時間・場所（宮城教育大学 音楽棟）だけで、名前や学籍番号は入れない。

- **コピー**（まとめて予約ができる人だけ。管理者モード、または設定で全員に許可したとき）: 予約の詳細の見出しの右のボタン（スマホでは絵だけ）。時間・氏名・学籍番号・備考・色を引き継いだ「予約のコピー」画面が開く。部屋と日付の欄の代わりに、「元の予約: 日付 部屋 時間」と、**日**（7日分のボタン。‹ › で1週間ずつ動かす。今日より前・定休日は選べない）と**部屋**（部屋のボタンの一覧）が出て、どちらも複数選べる。予約するのは「選んだ日 × 選んだ部屋」から元の予約と同じ組み合わせを除いたもの（同じ日の別の部屋にも、別の日の同じ部屋にもコピーできる）。初めは元の日・元の部屋を選んだ状態（0件）。元の日・部屋のボタンには小さな点。部屋の欄のすぐ下に、予約する日・部屋（4件まで）か件数を出す。くり返し予約も使え、選んだ日それぞれを最終日まで毎週（隔週）予約する（「毎日」は使えない）。2件以上ならまとめて予約（`createBulkReservations` に組み合わせの一覧 `pairs` を渡す）。終わった予約もコピーできる。
- 予約の帯を押すと詳細（部屋・日付・時間・予約者・備考）。編集用パスワードが付いた予約は、その4桁を入れて「変更」「取消」。管理者モードでは不要。
- 終了した予約は変更・取消できない（管理者を除く）。「管理者のみ」の部屋の予約は、管理者だけが変更・取消できる。
- **まとめ予約の1件**:
  - 取消: 「この日以降の分（全部屋）をまとめて取り消す」を選べる。
  - 変更: 「この日以降の分もまとめて変更する」を選べる。まとめて変わるのは時間・氏名・学籍番号・備考で、日付と部屋はそれぞれのまま。1件でも重複などで変更できなければ、どれも変更せず、変更できない日の一覧を出す。
- PC では、予約の帯にマウスを0.3秒乗せると詳細カードが出て、マウスについて動く。画面の端では反対側に回る。

### 2.8 限定公開の部屋・閲覧パスワード

- 部屋の予約制限が「限定公開」の部屋（演習室など）は、限定公開のパスワードを入れた端末と管理者にだけ、部屋も予約も休館も返す。一般の利用者には部屋があること自体を出さない（サーバーが返さない）。

- 閲覧パスワード（設定）を決めると、予約表を見る・予約するのにパスワードが必要になる（端末に覚える）。通常は使わない。

### 2.10.5 アプリのように使う（ホーム画面に追加）

- `web/manifest.webmanifest`（名前・アイコン `icon-192.png` / `icon-512.png` / `icon-maskable-512.png`）と `web/sw.js`（Service Worker）。https のときだけ `sw.js` を登録する。

- やめるときは、`sw.js` の中身を「自分を登録解除して保存を消す」内容に差し替えて公開する（保守マニュアル 03 の 9章）。

### 3.2 管理用パスワードの誤入力

- 誤入力は全体で数え、10回で10分間受け付けない。
- ただし、管理画面にログインできた端末には印（`adminDevice`）を渡して覚え（最大30台、古い順に忘れる）、その端末の誤入力は端末ごとに数える。誰かが全体をロックさせても、いつもの端末からは入れる。
- 予約の編集用パスワードの欄に4桁の数字以外を入れた場合は、管理用パスワードとして照合し、外れは上の回数に数える。

### 3.3 パスキーでのログイン

- 管理用パスワードの代わりに、Face ID・Touch ID・端末のロック解除で管理画面に入れる。高速キャッシュ（`CACHE_API_URL`）を使っていて、ブラウザがパスキーに対応しているときだけ、ログイン画面に「パスキーでログイン」、「設定」タブに「パスキー」の欄が出る。管理用パスワードはそのまま使える（予備の入り口。初めての登録や、Cloudflare をやめたときに使う）。
- **登録**: 管理用パスワードかパスキーでログインした状態で「この端末を登録」。名前は端末の種類と登録日（例: iPhone（2026/10/10 登録））。一覧に最後に使った日時が出て、削除できる（最大30個）。
- **仕組み**: パスキーの署名は GAS では確かめられないので、高速キャッシュ（`cache/worker.js` の `/passkey/…`）が確かめる。
  1. ログイン: 画面が `/passkey/challenge` で確認用の文字列（有効3分、Worker の署名付き）をもらい、端末で Face ID などをして署名し、`/passkey/login` に送る。Worker は、サイト（`PASSKEY_ORIGIN`・`PASSKEY_RP_ID`）・本人確認の済みの印・登録済みの公開鍵での署名を確かめ、同じ確認用の文字列の使い回しを断る。通れば「ログインの印」`pk1.有効期限.番号.署名` を返す（12時間有効）。
  2. 画面はこの印を管理用パスワードの代わりに保存して送る（sessionStorage の `prr.adminPw`。予約表の管理者モードも同じ印で動く）。GAS の `verifyAdmin_` が、高速キャッシュとの合言葉（`CACHE_PUSH_TOKEN`）で署名と期限を確かめる。期限切れは「ログインし直してください」と出る。
  3. 登録・一覧・削除: GAS の `adminPasskeyTicket` が管理者に「許可証」`pkt.有効期限.署名`（5分有効）を出し、画面がそれを添えて Worker の `/passkey/register`・`list`・`delete` を呼ぶ。
- **置くもの**: Worker の D1 の表 `passkeys`（番号・公開鍵・方式・名前・登録日時・最後に使った日時）と `passkey_used`（使い終わった確認用の文字列、期限まで）。指紋や顔の情報、秘密の鍵は端末から出ない。
- 合言葉 `CACHE_PUSH_TOKEN` を変えると、パスキーでログインしている人はログインし直しになる（パスキーの登録は消えない）。
- 対応している署名の方式は ES256（iPhone・Mac・Android・Windows の多く）と RS256。

### 4.2 上限と回数制限（`SYSTEM` ほか）

| 対象 | 上限 |
| :--- | :--- |
| 予約の登録・変更・取消・まとめて予約 | 全体で毎分30件（`MAX_WRITES_PER_MINUTE`）。超えると「予約の操作が集中しています」 |

| 不具合報告 | 全体で10分に30件 |

### 4.3 サーバー側の覚え（CacheService）

- `getSchedule` は、同じ期間・同じ見え方（限定公開の有無）の結果を、予約・設定が変わるまで（最長60秒）覚えて返す（100KB 未満のときのみ）。予約・設定を変える処理（`withLock_` の中）が成功すると版（`schedVer`）が変わり、覚えていた分は使わない。
- スクリプトプロパティ（`ADMIN_PASSWORD`・`SPREADSHEET_ID`・`ADMIN_DEVICES`）は、読み出しが1日5万回までなので10分覚えておく（`prop_`）。書き換えは `setProp_` を通す。GAS の画面でプロパティを直接書き換えた場合、反映に最長10分かかる。

### 4.4 スプレッドシートのメニュー（「予約システム」）

初期セットアップ / 前年度の予約をアーカイブ / 管理用パスワードを設定 / 高速キャッシュに今すぐ送る / 高速キャッシュの自動送り直しを設定（`onOpen`）。

### 4.5 高速キャッシュ（Cloudflare Workers ＋ D1。`cache/worker.js`）

使うかどうかは切り替えられる。切り替えが空なら、今まで通り予約表は GAS から直接読む。

| 切り替え | 場所 | 空にすると |
| :--- | :--- | :--- |
| `CACHE_API_URL` | `web/config.js` | 予約表は高速キャッシュを使わない |
| `CACHE_PUSH_URL`・`CACHE_PUSH_TOKEN` | GAS のスクリプトプロパティ | GAS は写しを送らない |

- **写しの中身**: 一般の人の見え方（限定公開の部屋なし）の部屋・公開用の設定・休館・予約（`toPublic_` の形。編集用パスワードは含めない）。範囲は先月の1日から4か月先の月末まで（`SYSTEM.CACHE_MONTHS_AHEAD`）。閲覧パスワードを設定している間は、写しを置かない（`disabled`）。
- **送るとき**: `withLock_` の書き込みが成功したあと（ロックを外してから）、`pushCache_` が写しをまとめて `POST /push` で送る（合言葉は `Authorization: Bearer`）。版は送る直前の時刻で、Worker は今より古い版を捨てる。送れなかったら `CACHE_DIRTY` を立て、5分ごとのトリガー `cacheRetry` が送り直す。日付が変わった最初の実行でも送る（範囲を進めるため）。スプレッドシートのメニュー「高速キャッシュに今すぐ送る」「高速キャッシュの自動送り直しを設定」。
- **読むとき**: 予約表の `getScheduleFast` が `GET /schedule?from&to` を読む。次のときは GAS から読む: 管理者モード、限定公開の部屋を表示中、自分が書き込んでから2分以内、写しの範囲外・写しなし（`MISS`）、通信の失敗、2.5秒以内に返事がない、画面と写しの版（`apiVersion`）が違う。どちらから読んだかは、更新ボタンの説明（`title`）に出る。
- **Cloudflare 側**: D1 の表 `cache(k, v)` に、`meta`（版・部屋・設定・休館・範囲）と月ごとの予約 `m:YYYY-MM` を入れる。`main` に push すると、GitHub Actions（`.github/workflows/cache-deploy.yml`）が Worker を公開する（`CLOUDFLARE_API_TOKEN` などの Secrets がなければ何もしない）。
- **パスキー**（3.3）: `POST /passkey/challenge`・`login`・`register`・`list`・`delete`。返事は管理画面のサイト（`PASSKEY_ORIGIN`）からだけ読める。`wrangler.toml` の `PASSKEY_RP_ID` を空にすると使えなくなる。
- **無料枠**（2026年10月時点）: Workers は1日10万回、D1 は1日に読み500万行・書き10万行。1回の送信で書くのは7行ほど。

## 6. 既知の制限・未解決

- **iPad の Safari のスクロールバー**: 縦のバーが縞模様の行の下に隠れて途切れて見えたため、表の箱（`.main`）に `z-index: 0` を付けて中身を閉じ込めた（2026-10-10。実機で確認待ち）。横向き（12.9インチ）で横のバーが画面の下端より上に出る件は、原因が未特定。
- **Safari のパスワード管理が「備考」や編集用パスワードの欄で出ることがある**: 編集用パスワードを伏せ字にしているため、Safari がパスワード欄とみなし、すぐ上の「備考」をユーザー名と勘違いする（そのサイトのパスワードを保存している端末＝主に管理者の端末で出る）。伏せ字をやめれば止まるが、人目に触れる画面で守られている見た目を優先して伏せ字のままにしている（2026-10-10 に試して取り消し）。

- **iPhone でキーボードを開くと「予約確定」が隠れる**: キーボードの上のバー（∧ ∨ ✓）に重なる。試して撤回した方法: ダイアログを見えている範囲に縮める（入力欄がずれる）、帯をキーボードの上に持ち上げる（Safari の動きとぶつかる）、キーボードの高さの余白を足す（効果がなく、iPad の不具合報告などでダイアログの下に大きな空白が出た）。改善点として残している。
- **Safari の下のバーの裏まで表を伸ばせない**: 表だけがスクロールする作りのため。ページ全体をスクロールさせる作りには変えない方針（縦横に動く表と相性が悪い）。
- **光の屈折**: 上部の帯・ダイアログ・詳細カードの縁の屈折は、Chrome・Edge だけで出る（SVG フィルタ）。Safari はぼかしのみ。
- **予約者の名前と学籍番号は、URL を知っている人なら誰でも見られる**（りざぶ郎と同じ考え方）。
- iPhone が「学籍番号／所属」の欄に保存済みのパスワードを候補として出すことがある。

## 7. 見た目の決まり

- 説明文は書かない。見ればわかることは省き、どうしても要る説明だけを「i」ボタン（`.info`。macOS の info.circle に似せた細い線の丸に立った i、薄い灰色。i は文字ではなく点と棒で描く（フォントの差でずれないように）。どこでも同じ 12px で、隣の文字の上下の真ん中にそろえる）に入れる。マウスのある端末では、macOS の説明（ヘルプタグ）のように 0.5秒止めるとマウスの右下に小さな札（`.tip-pop`）が出て、外すと消える。指の端末では押すと出て、もう一度押すかほかを押すと消える。今は管理画面だけで使っている。

- 端末の設定に合わせて、ライトモードとダークモードを自動で切り替える（予約表・管理画面・プライバシーポリシーのすべて）。URL に `?dark` を付けると常にダーク、`?light` を付けると常にライト（確認用）。読み込み時に白く光らないよう、`<head>` の中で `html.dark` を付ける。
- iOS 風の控えめなガラス（半透明＋ぼかし＋縁の光）。ボタン・選択欄は角丸 11px、ダイアログ 22px。主役のボタン（新規予約・予約確定など）だけ青（#007aff）。
- ダークモード（iOS の設定アプリに合わせる）: 背景は黒、表・カードは #1c1c1e、ふつうのボタンは上端だけかすかに光る平らな濃い灰色（#262628）。青いボタンは少し明るい平らな青（#3b8ff5）に縁がかすかに光る輪郭（iOS の決定ボタン風）。ダイアログと PC の詳細カードは、後ろの表がぼけて透けるすりガラス（灰色 52〜55% ＋ぼかし 24〜30px）。色は各ファイルの「ダークモード」の層（`html.dark` で始まる指定）にまとめてある。
- 予約の帯: 予約済み = オレンジ（#ff9500 系、ダークでは #ff9f0a 系）、この端末の予約 = 青（#007aff 系、ダークでは #0a84ff 系）。
- ぼかしに対応していない環境・「透明度を下げる」設定では、透けない面にする。
- デザイン変更の前の版はタグ `v0.3.3-beta` に保存。
