# デプロイ手順

練習室予約システムは、次の2つでできています。

| 部分 | 置き場所 | 中身 |
| :--- | :--- | :--- |
| 画面（予約表・管理画面） | GitHub Pages（リポジトリの `web/` フォルダ） | `index.html`・`admin.html`・`api.js`・`config.js` |
| サーバー（データの読み書き） | Google Apps Script（GAS）＋スプレッドシート | `gas/Code.gs`・`gas/appsscript.json` |

画面は GAS の URL に `fetch()` でデータを問い合わせます。GAS は画面を返さず、JSON だけを返します。

| URL | 用途 |
| :--- | :--- |
| `https://miyakyo-music.github.io/yoyaku/` | 予約表（利用者に案内する URL） |
| `https://miyakyo-music.github.io/yoyaku/admin.html` | 管理画面（予約表右上の「管理」からも開ける） |
| `https://script.google.com/macros/s/……/exec` | GAS の API。利用者には案内しない（開くと動作確認用の JSON が表示される） |

---

## A. GitHub の準備（初回のみ。2026年10月に作成済み）

### A-1. Organization（組織アカウント）

画面のコードは、個人ではなく組織アカウント **`miyakyo-music`** のリポジトリ **`yoyaku`** に置いています。担当者が卒業しても、Owner を後任に追加するだけで引き継げます。

作り直す場合の手順：

1. 管理者になる人が、それぞれ個人の GitHub アカウントを作り、2段階認証を設定する。
2. github.com にログインし、右上の「＋」→ **New organization** → プランは **Free**。
3. Organization name（URL の一部になる）、Contact email（学科の共有アドレスか専任教員のアドレス）を入れ、所属は **A business or institution** で大学・学科名を入れる。
4. **専任教員を含めて2人以上を Owner** にする。
5. **New repository** でリポジトリを作る（**Public**。Free プランで GitHub Pages を使うには公開が必要）。

> リポジトリは誰でも見られますが、管理用パスワード・予約データはコードに含まれません（GAS とスプレッドシートにだけあります）。

### A-2. GitHub Pages を有効にする

1. リポジトリの **Settings > Pages** を開き、**Source** を **GitHub Actions** にする。
2. 以後、`main` ブランチの `web/` フォルダが変わるたびに、`.github/workflows/pages.yml` が自動で公開する（1〜2分）。進み具合はリポジトリの **Actions** タブで見られる。

## B. スプレッドシートと GAS の準備（初回・担当交代時）

作業には、共有ドライブにファイルを作成できる大学の Google アカウントを使います。

### B-1. スプレッドシートを作る

1. Google ドライブで、**学科または専任教員の「共有ドライブ」** に空のスプレッドシートを作り、名前を付ける（例：`練習室予約システム`）。
   > 個人の「マイドライブ」には作らないでください。作成者が卒業してアカウントが消えると、データごと消えます。

### B-2. コードを貼り付ける

1. スプレッドシートのメニュー **「拡張機能 > Apps Script」** を開き、プロジェクトに名前を付ける（例：`練習室予約`）。
2. 最初からある `コード.gs` の中身をすべて消し、`gas/Code.gs` の内容を貼り付ける。
3. 左の歯車「プロジェクトの設定」で **「『appsscript.json』マニフェスト ファイルをエディタで表示する」** にチェックを入れ、エディタに戻って `appsscript.json` の中身を `gas/appsscript.json` の内容に置き換える。
4. 保存する（`⌘ + S` / `Ctrl + S`）。

> HTML ファイルは不要です。以前の版の `Index`・`Admin` が残っていたら削除してください。

### B-3. 初期セットアップ

1. エディタ上部の関数の選択欄で **`setup`** を選び、**「実行」** を押す。
2. 初回は権限の確認が出る：「権限を確認」→ 自分のアカウント →（「Google で確認されていません」と出たら）「詳細」→「（プロジェクト名）（安全ではないページ）に移動」→「許可」。
3. 「予約台帳」「部屋マスタ」「休館・利用停止」「設定」「操作ログ」「不具合報告」シートが作られる。
4. スプレッドシートを再読み込みし、メニュー **「予約システム > 管理用パスワードを設定」** で6文字以上のパスワードを設定する。

### B-4. ウェブアプリとしてデプロイする

1. Apps Script エディタ右上の **「デプロイ > 新しいデプロイ」** → 種類の歯車から **「ウェブアプリ」**。
2. 次のように設定して「デプロイ」：

   | 項目 | 設定値 | 理由 |
   | :--- | :--- | :--- |
   | 次のユーザーとして実行 | **自分** | 利用者がスプレッドシートに直接アクセスせずに済むように |
   | アクセスできるユーザー | **全員** | Google にログインしていない人も使えるように |

3. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピーする。
4. その URL をブラウザで開き、`{"ok":true,"service":"練習室予約API",…}` と表示されることを確認する。
   - Google のログイン画面が出る場合は「アクセスできるユーザー」が「全員」になっていません。

> 「アクセスできるユーザー」に「全員」が出ない場合は、大学の Google Workspace の管理者が外部公開を制限しています。情報システム担当に確認してください。

### B-5. 画面に GAS の URL を設定する

1. リポジトリの `web/config.js` を開き、`window.GAS_API_URL = '';` の `''` の中に、B-4 でコピーした URL を貼る。
   - GitHub の画面で直接編集する場合：ファイルを開いて鉛筆アイコン →書き換え →「Commit changes」。
2. 1〜2分後に予約表を開き、表示されることを確認する。

### B-6. 動作確認

1. 予約表で予約・変更・取消ができることを確認し、テスト予約は取り消しておく。
2. 管理画面（予約表右上の「管理」）に管理用パスワードでログインし、練習室の名前・特徴タグ、利用時間、予約表のタイトルなどを実物に合わせる。
3. iPhone の Safari でも予約できること、ページを開き直したときに氏名が自動で入ることを確認する。

## 修正したとき

| 変更したもの | 反映のしかた |
| :--- | :--- |
| 画面（`web/` の中） | `main` に push するだけ。1〜2分で公開される |
| サーバー（`gas/Code.gs`） | Apps Script エディタに貼り替えて保存 →「デプロイ > デプロイを管理」→ 公開中のデプロイの鉛筆アイコン →「バージョン」で **新バージョン** →「デプロイ」 |

- サーバー側は、**「新しいデプロイ」を使わない**でください。URL が変わり、`web/config.js` の書き換えが必要になります。保存しただけでは反映されません。
- 画面とサーバーの両方にかかわる変更（`web/api.js` と `gas/Code.gs` の `API_VERSION` を上げる変更）は、**先に GAS を新バージョンでデプロイしてから** 画面を push する。版が食い違っている間は、画面の下に「システムが更新されました。ページを再読み込みしてください。」と表示されます。
- GitHub Pages はブラウザに最大10分ほどキャッシュされることがあります。反映されないときは再読み込みしてください。

## 公開前に変更を試したいとき

- 画面とサーバーの両方を手元で試せます（README の「動作確認（ローカル）」）。本物の `gas/Code.gs` がブラウザ上で動きます。
- GAS の「デプロイ > デプロイをテスト」の URL（末尾が `/dev`）は、ログインした編集者しか呼べないため、画面からの接続には使えません。

## 担当者が交代するとき

GAS のウェブアプリは **デプロイした人のアカウント** で動きます。前任者のアカウントが失効すると止まるので、卒業・異動の前に後任者が B-4（新しいデプロイ）と B-5（`config.js` の書き換え）を行ってください。予約表の URL（GitHub Pages）は変わらないので、案内し直す必要はありません。詳しくは [運用・引き継ぎマニュアル](運用・引き継ぎマニュアル.md) の「3. 卒業・担当交代時」。

## よくあるトラブル

| 症状 | 原因と対処 |
| :--- | :--- |
| 「接続先が設定されていません」と出る | `web/config.js` の `GAS_API_URL` が空（B-5） |
| 「通信に失敗しました」と出る（ネットにはつながっている） | GAS のデプロイの「アクセスできるユーザー」が「全員」でない、URL が間違っている、またはデプロイしたアカウントが失効している。GAS の URL をブラウザで開いて JSON が出るか確かめる |
| 「シート『予約台帳』が見つかりません」と出る | B-3 の `setup` を実行していない |
| メニュー「予約システム」が出ない | スプレッドシートを再読み込みする。それでも出ない場合は `setup` を一度実行する |
| 管理画面に「管理用パスワードが設定されていません」と出る | B-3 の4を行う |
| GAS を修正したのに変わらない | 新バージョンでデプロイしていない |
| 画面を修正したのに変わらない | Actions タブで公開が終わっているか確認し、ページを再読み込みする |
