# 練習室予約システム 運用・引き継ぎマニュアル

## 1. 保管場所（最重要）

- スプレッドシートとApps Scriptは、**学科または専任教員の「共有ドライブ」内**に置く。
- 個人の「マイドライブ」に移動・コピーしない。作成者が卒業してアカウントが消えるとファイルも消えます。
- 画面のコードは GitHub の組織アカウント **`miyakyo-music`** のリポジトリ **`yoyaku`** にある。予約表の URL は `https://miyakyo-music.github.io/yoyaku/`。

## 2. 年度切り替え（毎年4月の最初の週）

1. スプレッドシートを開き、メニュー「**予約システム > 前年度の予約をアーカイブ**」を実行する。
2. 確認画面で「OK」を押す。
   - 3月31日以前の予約が「予約台帳_YYYY年度」シートへ移動します。
   - 4月1日以降の予約（先に入っていたもの）は「予約台帳」に残ります。
3. 必要なら、アーカイブシートを右クリック「別のスプレッドシートにコピー」で別ファイルに保存し、元のシートは削除してよい。
4. 部屋の増減・名称変更があれば「部屋マスタ」シートを編集する（部屋IDは変更しない）。

## 3. 卒業・担当交代時（毎年3月）

GAS（サーバー）は「デプロイした人」のアカウントで動きます。前任者のアカウントが失効する前に、次の手順を行います。予約表のURL（GitHub Pages）は変わらないので、掲示物・QRコードはそのままで構いません。

1. **GitHub**：前任の Owner が、後任者を組織 `miyakyo-music` の **Owner** に招待する（github.com の組織ページ → People → Invite member → Role: Owner）。Owner が常に2人以上いるようにする。
2. 後任者（学生または担当教員）が、共有ドライブ上のスプレッドシートを開く。
3. 「拡張機能 > Apps Script」→「デプロイ > 新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**／アクセスできるユーザー: **全員**
4. 権限承認後に表示される**新しいURL**（末尾 `/exec`）を、リポジトリの `web/config.js` の `GAS_API_URL` に書き換える（GitHub の画面で鉛筆アイコンから編集して「Commit changes」）。
5. 1〜2分後に予約表が表示され、予約できることを確認したら、前任者のデプロイは「デプロイを管理 > アーカイブ」してよい。
6. 管理画面「パスワード」タブ（またはメニュー「予約システム > 管理用パスワードを設定」）で管理用パスワードを新しいものに変更する。
7. 前任者を GitHub の組織から外す（卒業後も協力してもらう場合は Member のままでもよい）。

## 4. 管理画面

予約表の右上「管理」（スマホでは⚙）から開き、管理用パスワードでログインします。
練習室の追加・削除・名前変更・並べ替え、利用時間・予約単位・各種制限、休館・利用停止の登録、管理用パスワードの変更ができます。

## 5. よくある対応

| 状況 | 対応 |
| :--- | :--- |
| 編集用パスワードを忘れた人がいる | 編集用パスワードの欄に管理用パスワードを入れて変更・取消する、または「予約台帳」の該当行を削除する |
| 調律・入試・清掃などで部屋を使えない日がある | 管理画面「休館・利用停止」で日付・対象・時間帯・理由を追加 |
| 毎週決まった曜日が休み | 管理画面「利用時間・制限」の定休日にチェック |
| 1人が長時間押さえすぎる | 管理画面「利用時間・制限」で最大予約時間・予約受付期間を設定 |
| 特定の部屋を教員専用にしたい | 管理画面「練習室」で予約制限を「管理者のみ」にする（故障中なら「使用停止」） |
| 演習室を一部の人（教員・音楽科の学生・オケ幹部など）だけに使わせたい | 管理画面「練習室」で予約制限を「限定公開」にし、「パスワード」タブの「限定公開の部屋（演習室など）」でパスワードを設定。使う人にだけ、パスワードと入口の URL（`https://miyakyo-music.github.io/yoyaku/?limited`）を伝える。一般の利用者には演習室は表示されない |
| 限定公開のパスワードが広まった | 管理画面でパスワードを変える（記憶済みの端末でも表示されなくなるので、使う人に新しいパスワードを伝え直す） |
| 練習室が増えた・減った | 管理画面「練習室」で追加・削除（予約が残っている部屋は「使用停止」に） |
| 誰が予約を消したか知りたい | 「操作ログ」シートを見る |
| いたずら予約がある | 「予約台帳」の該当行を削除する |
| 授業の予約を学期途中で終える | 予約表で該当授業の最初に消したい日をタップ →「この日以降の同じくり返し予約もまとめて取り消す」にチェックして取り消す |
| 教員がくり返し予約をしたい | 管理用パスワードを伝えるか、管理者が代わりに入力する |
| 画面に「シートが見つかりません」と出る | シート名が変更されていないか確認。消えた場合は「予約システム > 初期セットアップ」 |
| 「通信に失敗しました」と出る（ネットにはつながっている） | GASをデプロイしたアカウントが失効している可能性 → 「3. 卒業・担当交代時」の手順でデプロイし直す |
| 画面を直したい | リポジトリの `web/` を編集して `main` に push（[デプロイ手順](デプロイ手順.md)） |

## 6. 触ってはいけないもの

- シート名「予約台帳」「部屋マスタ」「休館・利用停止」「設定」「操作ログ」「不具合報告」、および1行目の見出し
- 「設定」シートのA列（項目名）
- 「部屋マスタ」の部屋ID（予約データと結びついています）
